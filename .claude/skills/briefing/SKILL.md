# Skill: /briefing [exec|vp] [workstream?] | /briefing [workstream]

## --help

When invoked as `/briefing --help` or `/briefing -h` — print this and stop:

```
/briefing — Generate a status briefing from Lore intelligence

Usage:
  /briefing                          → prompts for audience
  /briefing exec [workstream]        → executive briefing (CTO, CPO, SVP Eng)
  /briefing vp [workstream]          → VP briefing (Solution Lead, Sol Eng Lead)
  /briefing leads                    → delivery lead briefing, all workstreams
  /briefing weekly                   → weekly plan (strategic compass for the week)
  /briefing [workstream]             → delivery lead briefing, one workstream

Examples:
  /briefing exec
  /briefing vp infrastructure
  /briefing weekly
  /briefing platform-services

Tip: Workstream names are resolved from knowledge/workstreams.md (fuzzy match).
     /briefing leads = today's tactical checklist.
     /briefing weekly = this week's strategic compass.
```

## Argument Parsing

```
/briefing                          → ask "For whom? exec / vp / leads / weekly — or name a workstream"
/briefing exec                     → executive briefing, all workstreams
/briefing exec [workstream]        → executive briefing filtered to one workstream
/briefing vp                       → full VP briefing, all workstreams
/briefing vp [workstream]          → VP briefing filtered to one workstream
/briefing weekly                   → weekly plan (strategic compass for the week)
/briefing [workstream]             → delivery lead briefing filtered to one workstream
/briefing leads                    → delivery lead briefing, all workstreams (alias)
```

Workstream resolution: match the argument against `knowledge/workstreams.md`.
Fuzzy matching — "eng", "engineering", "ws1" all resolve to the matching workstream.
If ambiguous: ask. If unknown: list valid workstream names from workstreams.md.
No hardcoded workstream list here — always resolve dynamically from knowledge/workstreams.md.

|---------|----------------|-------------|------|

## Briefing Header (all variants)

Every briefing output MUST start with this header block — before any content:

```
> **LORE** — Intelligence & Delivery Engine
> Project: {PROJECT_NAME} · Source: Lore Knowledge Graph
> Generated: [DATE] · Coverage: [X]% · Confidence: [High/Medium/Low]
> ───────────────────────────────────────────────────────────────
```

Rules for the header:
- DATE = today's date (YYYY-MM-DD)
- Coverage = from pull metadata (latest daily log)
- Confidence = High (>7 days log data), Medium (3-7 days), Low (<3 days or onboarding mode)
- The header is a blockquote — visually distinct from briefing content
- Never omit the header, even in onboarding mode
- {PROJECT_NAME} is derived from `.lore/config.md`

## State File = Leads Briefing

The state file IS a full leads-level briefing, generated by `/pull` (Phase 7).

```
log/state/YYYY-MM-DD.md  (today or most recent)
```

**For `/briefing leads`:** If state exists and is ≤24h old → serve directly (add header + provenance footer). No additional loading needed.

**For `/briefing exec` and `/briefing weekly`:** State is the primary summary. Condense or extend as the variant requires. Only load additional knowledge files if the specific angle needs more depth than the state provides (e.g. exec needs watch-list escalation history, weekly needs trend comparison across prior weeks).

**If no state file or >24h old:** Fall back to full knowledge file reads as specified in each variant template. Mark freshness accordingly in the provenance footer.

## Rules (all variants)

- Never invent status. If unknown: "No data – check source."
- Stalled = no log entry change in 7 days. Calculate from log dates.
- If milestone date has passed with no completion logged: mark 🔴 automatically.
- Suggest /escalate or /ask for every stalled item (vp and leads only — never in exec).
- Facts and AI interpretation are never mixed in the same section.
- exec: maximum half a page. No action items. No /escalate suggestions.
- vp: maximum 2 pages (full), 1 page (filtered).
- leads: maximum 2 pages (full), 1 page (filtered).
- If more: summarize, link to /context [ID].
- Always show context coverage % at end (vp and leads).
- If log data is thin (< 5 days): say so, reduce confidence accordingly.
- Never show items already escalated and awaiting response – mark as [waiting].
- Exec escalation threshold: only items where partner/sales is stuck, budget is insufficient, or cross-solution priority conflicts can't be resolved at VP/Sr Dir level. Everything else stays at VP level.
